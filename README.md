# リポジトリ

## 全体方針
* 常にリモートの更新をチェックする。

## ディレクトリ構造
* `./<core_library_name>`
    - コアライブラリ。
* `./scripts`
    - 各スクリプトは、コアライブラリを呼び出し、一定の処理を行う。例えば、学習、評価、結果の解析、等。
    - 書き方は、サンプルスクリプト(`./scripts/sample_script.py`) に **よく似せる**。
* `./exp`
    - 実験管理用のスクリプト群。`./scripts` のスクリプトを、様々な引数で呼んだり、その結果を出力したりする。
    - 実験は基本、このスクリプトで行う。`./scripts/*`は直接呼ばない。
    - 書き方
        * サンプルスクリプト(`./exp/00.sample_exp.py`) に **よく似せる**。例えば:
            - 同じライブラリを呼ぶ。
                * 例: `lab`, `script_engine`, `logger_setup`
                    - これらのライブラリはローカルに存在するので、`requirements.txt`への記載は不要。
            - 空行の間隔を取る。
            - スクリプトにオプションを付与しない。
            - 設定は`settings.py`に押し込める。
        * シンプルに保つ。例えば:
            - 余計な関数を作らない。
            - ガード節を多用しない。
    - ファイル構成と命名
        * メイン実験のスクリプトの命名は、「数字番号+内容」とする。
            - 例) `00.generate_data.py`, `01.train_LLM.py`, `02.evaluate_LLM.py`, `03.analyze_results.py`。
            - `./exp/00.sample_exp.py`は無視して`00`から書き始めること。
            - 意味的に"別系統"となったら、番号の桁を上げる。
                * 例) `10.ablate_attention.py`, `11.logic_lense.py`
        * 細かい設定の違いを別のスクリプトとして作らない。設定は、スクリプトの中で回す。
            - 例) 「別設定でのデータの生成」は`00.generate_data.py`の中で回す。
        * メイン実験ではないスクリプトは、付録番号`A00, A01, A02, ...`を使う。
            - 意味的に別系統になったらアルファベットを上げる: `B00, B01, B02, ...`。
* `./outputs`
    - `./exp`の出力ディレクトリ
    - 各スクリプトの出力先の命名: `./exp/A00.foo_bar.sh` の出力先は、`./outputs/A00.foo_bar.sh/2026-06-28.{実験条件の概要: 例えば"test_run"等。}/`とする。
        * 日付けは手で打ち込む。自動化しない。
* `./data`
    - リソース置き場。
* `./ipynb`
    - Jupyter Notebook を使って、結果を分析・図示などする。
        * ただ、スクリプトで済むなら、それでよいかも。
* `./docs`
    - 人間・AIが直接書く文書はここに置く。逆にスクリプトが出す結果は`outputs/`に置くこと。
    - 例
        * `./docs/reports/`: レポート
        * `./docs/research_plan/`: 研究計画書
        * `./docs/paper/`: 論文の原稿
